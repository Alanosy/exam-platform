## 1. 统计口径（本服务最重要的一节）

### 1.1 什么答卷可以进统计

一张答卷 `exam_record` 必须**同时满足**三条才算「已入统」：

| # | 条件 | 说明 |
| :--- | :--- | :--- |
| 1 | `status = 'submitted'` | `answering`（答题中）、`expired`（超时作废）一律不进统计 |
| 2 | **主观题已阅完** | 该 record 不存在 `exam_mark_task`，**或** `exam_mark_task.status = 'finished'` |
| 3 | `del_flag = 0` | 逻辑删除 |

由此得出答卷的三态标记（`stat_status`，冗余在汇总表上，便于前端直接展示）：

| 状态 | 含义 | 是否计入任何数值 |
| :--- | :--- | :--- |
| `COUNTED` | 已入统 | ✅ |
| `PENDING_MARK` | 已交卷，但有主观题未阅完 | ❌ **完全不计** |
| `EXCLUDED` | 管理员标记作废（作弊 / 异常 / 免考） | ❌ |

### 1.2 为什么必须等阅卷完成

`exam_record.total_score` 在交卷瞬间只有客观题分；主观题分是 `writeBackMark` 一点一点累加回来的。
**如果不等阅卷就入统，会直接产生两类事故**：

1. **统计数字偏小且持续变化**：平均分、及格率、排名每阅一份卷就跳一次，业务方会认为系统数据不可信。
2. **排名与及格判定错误**：一个客观题 55 分、主观题 30 分的考生，被按 55 分判不及格并发放错误结论。

> 唯一例外：**本场考试完全没有主观题**（或该答卷没有待阅的 `exam_mark_item`），交卷即 `COUNTED`。
> 判定方式：交卷时若无 `exam_mark_task` 生成 → 直接入统。

### 1.3 前端强制表现（所有统计页统一）

- 每个统计区块右上角挂一行小字：**「已入统 42 / 应交卷 50 · 待阅卷 8」**
- 待阅数 > 0 时，页面顶部出现黄色提示条：
  `⚠ 仍有 8 份答卷在人工阅卷中，统计结果暂未包含。阅卷完成后将自动并入。 [去阅卷]`
- 提供开关 **「含待阅卷预览」**（默认关闭，关闭时数值为正式口径；打开时用客观题分做临时估算，并在所有数字上加灰色「预」角标，且**不提供导出**）
- 考试进行中时，统计页显示**近 5 分钟自动刷新**提示与「最后更新时间」

### 1.4 重考口径

`exam_record.attempt_no` 从 1 开始。统计提供两种口径，默认 **最后一次**：

| 口径 | 取值规则 | 场景 |
| :--- | :--- | :--- |
| 最后一次（默认） | `max(attempt_no)` | 看最终掌握情况 |
| 最好一次 | `max(total_score)` | 取证的考试 |

切换口径会**重新计算**（走预计算通道，不从缓存读）。

### 1.5 客观题 / 主观题划分

按 `question_type` 判定，做成字典 `exam_question_category` 便于后续扩展：

| 分类 | 题型 | 判分方式 | 统计指标 |
| :--- | :--- | :--- | :--- |
| 客观题 `objective` | `SINGLE` 单选、`MULTIPLE` 多选、`JUDGE` 判断、`BLANK` 填空、`MATCH` 匹配 | 自动判分 `correct=1/2` | **正确率**、选项分布、易错项 |
| 主观题 `subjective` | `SHORT_ANSWER` 简答、`ESSAY` 论述、`CODE` 代码、`UPLOAD_FILE` 文件上传 | 人工 / AI 预评后确认 | **得分率**、平均分、满分/零分占比 |

> 注意 `BLANK` 填空与 `MATCH` 匹配虽可自动判，但可能存在部分正确，一期按「全对才算正确」统计，二期再引入 `partial_score`。

## 2. 数据来源与计算策略

### 2.1 数据来源映射

| 统计需要 | 来源 | 获取方式 |
| :--- | :--- | :--- |
| 考试元信息（名称/时间/状态/创建人） | `ry-exam.exam` | 本库直查 |
| 试卷信息（总分/及格分/题目结构） | `ry-exam.paper`、`paper_question` | 本库直查 |
| 题目内容（题干/题型/难度/分值/正确答案） | `ry-exam.question`、`question_option` | 本库直查 |
| 阅卷状态与得分 | `ry-exam.exam_mark_task`、`exam_mark_item` | 本库直查 |
| **答卷记录与明细** | `ry-exam-answer.exam_record`、`exam_answer` | **Dubbo `RemoteExamAnswerService`** |
| 考生姓名 / 部门 | `ry-cloud.sys_user` / `sys_dept` | Dubbo `RemoteUserService` / `RemoteDeptService` |
| 知识点 | `question_bank_category`（一期） | 本库直查 |

### 2.2 实时 + 定时预计算：双轨设计

```
                 ┌──────────── 实时通道（秒级）────────────┐
   交卷 / 阅卷完成 ──▶ MQ 或 Dubbo 事件 ──▶ 增量重算单场 ──▶ Redis 计数 + 更新汇总行
                 └──────────────────────────────────────┘
                 ┌──────────── 批处理通道（分钟级）────────┐
   ruoyi-job 定时 ──▶ 扫描「脏考试」集合 ──▶ 全量重算 ──▶ 落 stat_* 汇总表 + bump version
                 └──────────────────────────────────────┘
                                    │
                    查询时：version 未变直接读汇总表；version 变了读汇总表+实时补丁
```

| 通道 | 触发 | 计算范围 | 落地 |
| :--- | :--- | :--- | :--- |
| **实时** | ① 交卷成功 ② `writeBackMark` 且 `finished=true` ③ 管理员改分 | 单场考试的**增量**（该 record 的加减量） | `stat_exam_summary` 行内 update + Redis `stat:exam:{id}` 缓存失效 |
| **定时** | `ruoyi-job` 每 10 分钟扫「近 24h 有变动的考试」；每日 02:00 全量重算近 7 天已结束考试 | 整场全量重算（自愈，修正增量漂移） | 覆写 `stat_exam_*` 全部行，`version + 1` |
| **手动** | 管理端点「重新计算」 | 整场全量 | 同上，写入 `stat_calc_task` 记录 |

> **为什么两条都要**：纯实时会因并发改分产生数值漂移且无法自愈；纯定时会让「阅卷完立刻看结果」的体验变成等 10 分钟。
> 定时任务挂在 `ruoyi-job`（框架已有），stat 只暴露一个 Dubbo 接口 `recalcExam(examId, force)` 供其调用。

### 2.3 缓存与一致性

- 缓存 key：`stat:exam:{examId}:{scope}`，TTL 30 分钟；`version` 变更即删
- 汇总表带 `calc_version`、`calc_time`、`calc_status（computing/success/fail）`
- 前端轮询「进行中考试」的统计页时，携带本地 `version`，未变则后端直接返回 `304-ish` 空响应体，减少传输

### 2.4 指标定义（公式，避免各端算法不一致）

| 指标 | 公式 | 备注 |
| :--- | :--- | :--- |
| 平均分 | `sum(total_score) / count(COUNTED)` | 保留 2 位 |
| 中位数 / 标准差 | 标准统计 | 分数段图用 |
| 及格率 | `count(passed=1) / count(COUNTED)` | `passed` 来自 `exam_record` |
| 优秀率 | `count(score >= 0.9 * 总分) / count` | 阈值可配，默认 90% |
| **难度系数 P** | 客观题：`正确率`；主观题：`平均得分 / 满分` | P 越大越容易 |
| **区分度 D** | `高分组正确率 − 低分组正确率`，高/低分组各取总分前 27% | D ≥ 0.4 优秀；0.3~0.39 良好；0.2~0.29 一般；< 0.2 需淘汰 |
| 客观题正确率 | `count(correct=1) / count(该题作答数)` | 未作答不计入分母 |
| 主观题得分率 | `avg(score) / full_score` | |
| 知识点掌握度 | `1 − Σ(该题失分) / Σ(该题满分)` | 加权而非简单平均，避免分值大题被淹没 |
| 选项选中率 | `count(选了该选项) / count(作答该题人数)` | 多选按人次 |

## 3. 数据模型（新增表，全部落在 `ry-exam`）

> 建表脚本放 `exam-back/script/sql/update/`，必须幂等；不改动任何已有表结构。

### 3.1 `stat_exam_summary` — 考试整体汇总（一场一行）

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `id` | bigint | 主键 |

| `paper_id` | bigint | 试卷ID快照 |
| `exam_name` | varchar(200) | 考试名快照（避免 join） |

| `attendance_rate` | decimal(5,2) | 参考率 % |
| `full_score` | decimal(10,2) | 试卷总分 |
| `pass_score` | decimal(10,2) | 及格分 |
| `max_score` / `min_score` / `avg_score` / `median_score` | decimal(10,2) | 最高/最低/平均/中位数 |

| `tenant_id` / `del_flag` / `create_by` / `create_time` / `update_by` / `update_time` | | 框架标准字段 |

### 3.2 `stat_exam_score_segment` — 分数段分布

| 字段 | 说明 |
| :--- | :--- |
| `exam_id` | 考试ID |
| `segment_label` | 段名，如 `0-59` / `60-69` |
| `segment_min` / `segment_max` | 区间（左闭右开，`max` 段右闭） |
| `person_count` | 人数 |
| `sort` | 排序 |

> 默认分段：`<60 / 60-69 / 70-79 / 80-89 / 90-100`。支持考试级自定义（存 `exam` 或参数表），一期先用默认。

### 3.3 `stat_exam_question` — 试题维度统计（一场 × 一题 一行）

| 字段 | 说明 |
| :--- | :--- |
| `exam_id` / `question_id` | 唯一键 `uk_exam_question` |
| `question_type` | 题型（冗余） |
| `question_category` | `objective` / `subjective` |
| `difficulty` | 难度（冗余） |
| `sort` | 题号 |
| `full_score` | 本题满分 |
| `answer_count` | 作答人数 |
| `correct_count` / `correct_rate` | 正确人数 / **正确率 %**（客观题） |
| `avg_score` / `score_rate` | 平均得分 / **得分率 %**（主观题） |
| `max_score` / `min_score` | 最高/最低得分 |
| `zero_count` / `full_count` | 零分人数 / 满分人数 |
| `blank_count` | 未作答人数 |
| `difficulty_index` | 难度系数 |
| `discrimination` | 区分度 |
| `wrong_count` | 错误人数（衍生，= answer_count − correct_count） |

### 3.4 `stat_exam_question_option` — 选项分布（客观题）

| 字段 | 说明 |
| :--- | :--- |
| `exam_id` / `question_id` / `option_key` | A/B/C/D |
| `select_count` / `select_rate` | 选中人次 / 选中率 % |
| `is_correct` | 是否正确选项（用于标出「易错项」） |

### 3.5 `stat_exam_user` — 考生维度统计

| 字段 | 说明 |
| :--- | :--- |
| `exam_id` / `user_id` / `record_id` / `attempt_no` | 唯一键 `uk_exam_user_attempt` |
| `account` / `user_name` / `dept_name` | 快照，避免跨库 join |
| `total_score` / `objective_score` / `subjective_score` | 得分 |
| `correct_count` / `wrong_count` / `blank_count` | 题目数 |
| `passed` | 是否及格 |
| `rank_no` | 排名（同分同名次） |
| `used_seconds` | 用时 |
| `submit_time` | 交卷时间 |
| `stat_status` | `COUNTED` / `PENDING_MARK` / `EXCLUDED` |

### 3.6 `stat_exam_knowledge` — 知识点维度统计

| 字段 | 说明 |
| :--- | :--- |
| `exam_id` / `knowledge_id` / `knowledge_name` | 一期 `knowledge_id` = `question_bank_category.id` |
| `question_count` | 关联题目数 |
| `full_score` | 知识点总分 |
| `avg_score` / `score_rate` | 平均得分 / 得分率 % |
| `wrong_count` / `wrong_rate` | 错误人次 / 错误率 % |
| `mastery` | **掌握度** = 1 − Σ失分 / Σ满分 |
| `weak_level` | `good` ≥80% / `normal` 60~80% / `weak` <60% |

### 3.7 `stat_calc_task` — 计算任务

`exam_id` / `trigger_type`（`auto` 交卷/`mark` 阅卷/`job` 定时/`manual` 手动）/`status` / `start_time` / `end_time` / `cost_ms` / `error_msg` / `version`

### 3.8 `stat_export_task` — 导出任务（异步）

`id` / `exam_id` / `export_type`（`overview`/`score`/`question`/`knowledge`/`detail`）/`param_json`（筛选条件快照）/`status`（`waiting`/`running`/`success`/`fail`）/`file_oss_id` / `file_name` / `row_count` / `operator` / `create_time`

> 超过 1000 行强制走异步任务 + 下载中心，避免请求超时。

### 3.9 知识点建模的取舍（需要你拍板）

| 方案 | 做法 | 成本 | 代价 |
| :--- | :--- | :--- | :--- |
| **A（推荐一期）** | 复用 `question_bank_category` 题库分类树当知识点 | 0 张新表 | 题目只能属于一个分类，一题多知识点做不到 |
| **B（二期）** | 新建 `exam_knowledge_point`（树，一门学科一棵）+ `exam_question_knowledge`（多对多） | 2 张新表 + 题目编辑页改造 | 需要题库侧配合录入 |

建议：**一期按 A 上线，表结构里 `knowledge_id` 保留语义中立**，二期切 B 时只改取值来源，不动统计逻辑。

## 4. 接口设计

### 4.1 REST（`/stat/**`，网关 StripPrefix=1，控制器写 `@RequestMapping({"", "/stat"})`）

| GET | `/stat/exam/{examId}/segment` | 分数段分布 | `exam:stat:list` |

| POST | `/stat/exam/{examId}/recalc` | 手动重新计算 | `exam:stat:recalc` |
| PUT | `/stat/exam/{examId}/record/{recordId}/exclude` | 标记 / 取消作废 | `exam:stat:exclude` |
| POST | `/stat/export` | 提交导出任务 | `exam:stat:export` |
| GET | `/stat/export/page` | 导出任务列表（下载中心） | `exam:stat:export` |

### 4.2 Dubbo

**`RemoteExamStatService`（对外提供）**
- `ExamStatBriefVo queryExamBrief(Long examId)` —— 供考试管理列表展示「平均分 / 及格率 / 参考率」
- `List<ExamStatBriefVo> batchBrief(List<Long> examIds)`
- `void markDirty(Long examId)` —— 供 answer/mark 调用，标记该考试统计已脏
- `boolean isCounted(Long recordId)`

**依赖（调用别人）**
- `RemoteExamAnswerService.listRecordsByExam / listAnswers / queryRecord`
- `RemoteExamService`（manage）取考试名、白名单
- `RemoteUserService` / `RemoteDeptService` 补全姓名部门
- `RemoteQuestionService` 取题干、选项、难度

### 4.3 事件接入点（改动点，需与答题/阅卷服务约定）

| 位置 | 动作 |
| :--- | :--- |
| `ExamRecordServiceImpl.doSubmit` 结尾 | 无主观题 → 直接 `recalc(examId, incremental)`；有主观题 → `markDirty(examId)` |
| `RemoteExamAnswerServiceImpl.writeBackMark` 且 `finished=true` | 该 record 置 `COUNTED` → `recalc(examId, incremental)` |

> 两处都 try-catch 只 warn：**统计挂了绝不能影响交卷和阅卷**。

## 5. 菜单与权限（插入 `ry-cloud.sys_menu`）

```
考试统计 (exam:stat:list)          /stat/dashboard   system/stat/dashboard/index
├─ 重新计算   (exam:stat:recalc)
├─ 作废标记   (exam:stat:exclude)
```

| 知识点分析 | `{考试名}_知识点分析_{日期}.xlsx` | 知识点 | 知识点/题目数/满分/平均得分/得分率/掌握度/薄弱等级 |
| 答卷明细 | `{考试名}_答卷明细_{日期}.xlsx` | 明细 | 考生/题号/题型/考生作答/正确答案/得分/结果/阅卷人 |

**规则**
- 走 `ruoyi-common-excel`（`@ExcelProperty` + `@ExcelIgnoreUnannotated`），字典值自动翻译
- **只导出已入统数据**；「含待阅卷预览」模式下导出按钮禁用并提示
- ≤1000 行同步下载；>1000 行进 `stat_export_task` 异步任务，前端去「下载中心」取
- 导出请求带完整筛选条件快照（`param_json`），下载的表格与屏幕所见一致
- 导出权限 `exam:stat:export`，记录操作日志

## 8. 非功能性要求

| 项 | 要求 |
| :--- | :--- |
| 租户隔离 | 所有表带 `tenant_id`，由框架拦截器自动追加；统计服务配置为**不忽略租户** |
| 数据权限 | 复用 `@DataPermission`，管理员只看自己创建/本部门考试；`creator_id` / `create_dept` 已在 `exam` 表 |
| 性能 | 统计只读，禁止压主库；汇总表 + Redis 双缓存；单场全量重算需分页拉取答卷，禁止一次全捞 |
| 大表 | `exam_answer` 按 `record_id` 查询走索引；题目维度统计按 `exam_id + question_id` 聚合 |
| 降级 | answer / mark / question 任一服务不可用 → 统计接口返回上一次成功结果 + `stale: true` 标记，前端显示「数据可能不是最新」 |
| 幂等 | `recalc` 用 Redis 锁（key = `stat:recalc:{examId}`）防并发重算 |
| 日志 | 重算、导出、作废标记打 info 日志 + `@Log` 操作日志 |

## 10. 需要你确认的 3 个决策点

1. **知识点方案**：一期复用题库分类树（快，一题一分类），还是直接建独立知识点表（准，但要改造题库录入页）？
2. **重考统计口径**：默认取「最后一次」还是「最好一次」？
3. **填空/匹配题**：一期按「全对才正确」统计，还是要支持部分分（`partial_score`）？
