# 考试系统微服务模块划分方案

> 基座：RuoYi-Cloud-Plus 2.6.2（Spring Boot 3.5 / Spring Cloud 2025 / Dubbo / Nacos / Sa-Token / MyBatis-Plus / 动态数据源）
> 核心约束：**用户、角色、菜单、权限、部门、岗位、字典、租户、日志、文件等全部复用原有框架，不新建任何同类模块。**
> 状态：Maven 模块骨架已创建完成（业务模块 6 个 + 接口模块 6 个），业务代码待补。

---

## 一、划分原则

1. **按限界上下文（DDD）拆**：以「题库 → 试卷 → 考试 → 作答 → 阅卷 → 统计」这条主链路为轴，每个环节是一个独立业务域。
2. **读写特性分离**：作答是高频写、考试期间有峰值；统计是重查询、只读。二者必须与低频的管理类服务隔离，避免相互拖垮。
3. **人工与自动分离**：自动判分在答题服务内完成（低延迟、考生等结果），人工阅卷是异步作业队列（任务分配、双评、复核），特性完全不同。
4. **不过度拆分**：主数据（题目、试卷）与交易数据（答卷、成绩）生命周期不同，但组卷规则和试卷结构强耦合，因此题库/试卷仍各自独立、而不与考试合并。
5. **复用优先**：凡框架已有的能力（鉴权、权限注解、租户隔离、操作日志、Excel 导入导出、OSS、定时任务、工作流）一律直接引用，考试域只写业务。

## 三、各模块职责与核心数据表

### 3.1 题库服务 `ruoyi-exam-question`

职责：
- 题型管理：单选、多选、判断、填空、简答、论述、计算、编程、材料/组合题
- 题目 CRUD、批量上下架、难度分级、解析与评分点
- 知识点树、章节树、题库分类（树形）
- 标签体系、题目查重
- 题目导入导出（Excel / Word），题干富文本 + 图片/音视频（走 `ruoyi-resource`）

核心表：`exam_question`、`exam_question_option`、`exam_question_answer`、`exam_category`、`exam_knowledge_point`、`exam_tag`、`exam_question_tag`

### 3.2 试卷服务 `ruoyi-exam-paper`

职责：
- 试卷 CRUD、试卷分类、试卷版本管理
- **固定组卷**（手动选题）与**随机组卷**（按题型/知识点/难度/数量/分值抽题）
- 试卷结构：大题/板块、题目分值、排序、总分校验
- 试卷预览、导出 Word/PDF、答题卡生成
- **试卷快照**：发布后固化，保证历史考试可追溯

核心表：`exam_paper`、`exam_paper_section`、`exam_paper_question`、`exam_paper_rule`、`exam_paper_template`

### 3.3 考试管理服务 `ruoyi-exam-manage`

职责：
- 考试计划/场次创建与编辑，绑定试卷
- 考试时间窗、时长、开考方式（统一开考 / 随到随考）
- **参考范围**：按用户、部门、角色、班级圈定考生
- 考试参数：及格线、允许次数、题目乱序、选项乱序、交卷方式、到时自动交卷
- 发布 / 下线 / 准考证 / 考试通知（复用 `ruoyi-job` + `common-sms`、`common-mail`）

核心表：`exam_info`、`exam_arrange`、`exam_scope`、`exam_participant`、`exam_config`、`exam_notice`

### 3.4 答题服务 `ruoyi-exam-answer`（重点）

职责：
- 开考：校验资格与次数 → 生成答卷 → 下发**试卷快照**
- 答题过程暂存（**Redis 优先，定时批量落库**，避免每题一次 DB 写）
- 交卷（手动 / 到时自动）、幂等防重复提交
- 客观题**自动判分**，主观题置为待阅状态
- 成绩生成、成绩查询、考试记录查询

核心表：`exam_answer_sheet`、`exam_answer_detail`、`exam_answer_record`、`exam_score`

> 性能要点：大题量表的写操作全部走 Redis + 异步落库；交卷判分走线程池/消息队列；该服务独立部署、独立数据库、可水平扩容。

### 3.5 阅卷服务 `ruoyi-exam-mark`

职责：
- 主观题阅卷任务分配（按题、按人、随机双评）
- 在线阅卷、打分、评语、评分点勾选
- 双评 / 多评、误差仲裁、复核
- 成绩修订与**改分审计日志**

核心表：`exam_mark_task`、`exam_mark_record`、`exam_mark_rule`

### 3.6 统计服务 `ruoyi-exam-stat`

职责：
- 成绩统计：平均分、最高/最低分、及格率、分数段分布、排名
- 试卷分析：难度系数、区分度、信度
- 题目分析：正确率、选项分布、易错项
- 错题分析、成绩单/报表导出
- 实现建议：走只读从库或 Elasticsearch，**不直接压主库**

核心表：`exam_stat_overview`、`exam_stat_question` 等汇总表（由 `ruoyi-job` 定时预聚合）

### 3.7 可选：练习服务 / 证书服务 / 防作弊服务

- `ruoyi-exam-practice`：章节练习、随机练习、每日一练、错题本、收藏；表 `exam_practice_record`、`exam_wrong_question`、`exam_favorite`
- `ruoyi-exam-cert`：证书模板、自动颁发、证书核验；表 `exam_cert_template`、`exam_cert`
- `ruoyi-exam-proctor`：活体检测、切屏/离屏事件、录屏存档、风控规则；表 `exam_proctor_task`、`exam_proctor_event`

## 五、服务依赖（Dubbo RPC）

```
组卷：  paper   → question   按条件（知识点/难度/题型）抽题
发布：  manage  → paper      校验试卷可用性、取试卷信息
开考：  answer  → manage     校验可否开考、参考资格、剩余次数
        answer  → paper      取试卷快照（仅开考时一次）
        answer  → question   取题目内容与标准答案（判分用）
阅卷：  mark    → answer     读取答卷明细、回写主观题得分
统计：  stat    → 各服务     离线/异步拉取聚合数据（禁止同步强依赖）
```

依赖方向严格单向：`question ← paper ← manage ← answer ← mark`，`stat` 旁路只读。**禁止反向调用**，避免循环依赖。

对应 Maven 依赖已在各模块 `pom.xml` 中配置好（只依赖对方 API 模块，不依赖实现类）。

## 十、小团队精简方案（3 个服务）

若人力有限，可先按「三域」落地，后续再拆：

| 服务名 | 归并内容 |
|--------|----------|
| `ruoyi-exam-core` | 题库 + 试卷 + 考试管理（主数据与管理域） |
| `ruoyi-exam-runtime` | 答题 + 判分 + 阅卷（运行域，高并发） |
| `ruoyi-exam-stat` | 统计分析域 |

关键判断标准只有一条：**只有「答题运行域」必须与其它服务物理隔离**，其余都是为了团队协作与独立迭代才拆的。

## 附：模块划分一句话总结

> 题库管「题」，试卷管「编排」，考试管理管「组织」，答题管「作答与判分」，阅卷管「人工评分」，统计管「分析与报表」；用户、角色、菜单、权限一律沿用框架。
