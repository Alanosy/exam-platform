## 4. 错题明细页：从全屏改成 Layout 内 + 统计与明细对不上

**问题1 全屏**：`/exam/wrong/detail` 原本写成顶层路由（`component` 直接是页面），

**问题2 首页统计 2 条、明细 0 条**：静态排查后把能确定的坑全堵了：
- 前端 `sourceId` 直接 `Number(sourceId)`，空值会变 NaN → 后端绑定 Long 失败 400 →
  前端 catch 成空列表。改成 `parseSourceId()` 只接受正整数。
- 后端 `lqw.ne(masterStatus, IGNORED)`：SQL 里 `NULL <> 'IGNORED'` 是 NULL，
  会把 master_status 为空的历史数据一起漏掉，与首页 Java 过滤口径不一致。
  改成 `and(w -> w.isNull(..).or().ne(..))`。
- **最隐蔽的一个**：`WrongQuestion.isDeleted` 上有 `@TableLogic`，

  exam-answer 的 try-catch 吞掉，表现就是「考试记录里有错题，错题本一条没有」。
  修法：mapper 加手写 SQL `selectOneIgnoreDeleted`（手写 SQL 不受 @TableLogic 影响，
  租户条件仍由拦截器追加）；命中已删除行时先 `restore()` 再 update
  （`updateById` 生成的 SQL 也带 `is_deleted = 0`，不复活就一行也更新不到）；
  syncWrong 改成逐条 try-catch，一条失败不拖垮整批。
- 来源改为**跟随最近一次答错**（`update.setSourceType/setSourceId`），
  否则「这场考试错了这道题」不会出现在该场考试的明细里，与「按考试记录统计」的诉求矛盾。
- detail 页加「当前范围」提示条 + 「查看全部来源」按钮 + 空态带范围文案，
  便于一眼区分是「真没有」还是「条件筛没了」。

## 7. 阅卷列表 500：cannot find converter from MarkTask to MarkTaskVo

**现象**：`GET /mark/task/list` → `io.github.linpeilie.ConvertException: cannot find converter
from MarkTask to MarkTaskVo`，栈落在 `MapstructUtils.convert`。

**根因**：项目用 **mapstruct-plus**，`MapstructUtils.convert()` 走的是
`Converter.convert()` → `ConverterFactory.getMapper(src, target)`，**没有任何兜底**，
找不到 `BaseMapper` 就直接抛 `ConvertException`。转换器必须由注解处理器生成：
- 同模块内的 VO：在 VO 上加 `@AutoMapper(target = XxxEntity.class)`
  （如 `ExamVo` / `QuestionVo` / `PaperVo`），处理器生成 `XxxToXxxVoMapper(Impl)`。
- **跨模块的 Remote*Vo**（VO 在 ruoyi-api-*，实体在业务模块，api 不能反向依赖）：
  在业务模块 `domain/convert/` 手写一个
  `@Mapper(componentModel = SPRING, unmappedTargetPolicy = IGNORE) interface XxxConvert extends BaseMapper<Entity, RemoteXxxVo>`。
  项目已有 `ExamConvert` / `PaperConvert` / `QuestionConvert` 就是这个约定。

**修法**：
- `MarkTaskVo` / `MarkQuestionVo` / `MarkLogVo` 分别补 `@AutoMapper(target = MarkTask/MarkItem/MarkLog.class)`
  （阅卷模块一个转换器都没生成，`target/generated-sources` 是空的）。
- 顺手补 `ruoyi-exam-answer` 的 `domain/convert/ExamRecordConvert`、`ExamAnswerConvert`
  （`RemoteExamAnswerServiceImpl` 的 queryRecord/listRecordsByExam/listAnswers 同样会炸，
  只是目前没有调用方所以没暴露）。

**排查技巧**：直接看 `ruoyi-xxx/target/generated-sources/annotations` 有没有
`XxxToYyyMapper.java` —— 没有就是缺注解。mapstruct-plus 生成的 `AutoMapperConfig__NN`
里 `unmappedTargetPolicy = IGNORE`，所以字段对不上只会警告不会编译失败。

## 8. 错题明细页查不到数据：19 位雪花ID 被 `Number()` 吃掉精度

**现象**：`/exam/wrong` 首页统计正常（sourceId=`2105488649030184961`），点「查看」进明细后
请求变成 `.../practice/wrong/list?sourceId=2105488649030185000`，查回 0 条。

**根因**：前端 `views/exam/wrong/detail.vue` 的 `parseSourceId()` 用 `Number(value)` 做校验。
雪花ID 19 位 > `Number.MAX_SAFE_INTEGER`（9007199254740991，16 位），一转就被四舍五入。
当时为了修「空值 → NaN → 后端 400」才引入的 Number，结果换了个坑。

**关键点**：后端 `ruoyi-common-json` 的 `JacksonConfig` 已经注册
`BigNumberSerializer`（`Long` / `Long.TYPE` / `BigInteger` → 字符串），
所以**后端返回的 Long 本身就是字符串**，前端拿到的是完整正确的值，
只要别在 JS 里做数值转换就不会丢精度。

**修法**：`parseSourceId` 改成正则校验 + 原样返回字符串：
```ts
const parseSourceId = (value?: string): string | undefined => {
  if (!value) return undefined;
  const text = String(value).trim();
  return /^\d+$/.test(text) ? text : undefined;
};
```
`initFromQuery` 里路由参数也统一 `String(q.xxx ?? '')` 读。
`WrongQuestionQuery.sourceId` 类型本来就是 `string | number`，不用改。
`practice.vue` 一直是 `String(route.query.sourceId)` + `/^\d+$/` 过滤，是安全的，没动。

**通用规则（本项目所有 ID 都适用）**：任何 `id / sourceId / examId / paperId / questionId`
在前端**禁止** `Number()` / `parseInt()`，一律字符串透传；需要校验就用 `/^\d+$/`。
`v-for` 的 `:key`、Map/Record 的 key 用字符串也一样安全。

## 12. 新增考试页白屏：ReferenceError: Cannot access 'form' before initialization

**现象**：点「新增考试」进 `/system/exam/edit` 直接报错，栈指向 `form.allowRetry` +
`setup (index.vue:256:1)` → `watch` → `ReactiveEffect.run`。

**根因（Vue 3.5.30 已确认的机制）**：`<script setup>` 里把
`watch(() => form.examType, ...)` 写在了 `const form = reactive(...)` **之前**。
Vue 创建 watch 时会**同步跑一次 getter** 取旧值——
`@vue/reactivity` 的 `watch()` 末尾：`if (cb) { if (immediate) job(true); else oldValue = effect.run(); }`
（`node_modules/@vue/reactivity/dist/reactivity.cjs.js:1936` 附近）。
所以 getter 里的 `form` 在 `const` 初始化前就被取值，命中 TDZ。
即使 `computed` 是惰性的没问题，只要有一条 `watch` 就会炸。
**不需要 `immediate: true` 也会触发**。

**修法**：`views/system/exam/edit/index.vue` 里把 `initFormData` + `const form = reactive(...)`
整块提到 `isFormal` computed 和那条 watch **之前**，并加注释说明为什么不能挪回去。

**通用规则**：`<script setup>` 里凡是 `watch` / `watchEffect` 的 getter 或回调要用到的响应式变量，
声明必须排在这些 watch 之前（函数体里用到的反而无所谓，运行时才执行）。

**批量排查脚本**（临时 `/tmp/tdz-scan.mjs`，思路备查）：扫 `src/**/*.{vue,ts}`，
只对 `<script>` 之后的行，找「`const x = reactive|ref|computed<`」的声明行之前
已出现 `x.` 且前后 6 行内有 `watch|computed|watchEffect(` 的文件。
全项目只剩 `views/system/paper/edit/index.vue` 的 `manualSelected` 一处命中，
确认是误报（在 `removeSelected()` 普通函数体里，运行时才调用，安全）。

## 阅卷进度条（views/system/mark/index.vue）

Element Plus `el-progress` 的 `text-inside` 文字固定 12px，而 `stroke-width=10` 时外层
`overflow:hidden`，文字被纵向裁掉；低进度时 inner 太窄，文字还会被横向裁掉。
修法：`stroke-width=20` + 圆角 10px + `:deep(.el-progress-bar__inner){ min-width:44px }`
（给低进度留文字空间）+ 0% 时去掉 min-width 并叠一个灰色 `0%` 文案（避免空条看不出是 0）。
后端 `MarkExamVo.progress` 是 `Integer`，前端只需 clamp 0~100。
