## 防作弊模块编译报错：Long → Boolean 映射不过

`ProctorSessionConvert extends BaseMapper<ProctorSession, RemoteProctorSessionVo>` 编译失败：

```
java: Can't map property "Long forceSubmit" to "Boolean forceSubmit".
Consider to declare/implement a mapping method: "Boolean map(Long value)".
```

**根因**：写 `RemoteProctorSessionVo` 时把 `forceSubmit` 顺手声明成了 `Boolean`，
而实体 `ProctorSession.forceSubmit` 是 `Long`（本项目 0/1 开关统一用 Long，如 delFlag）。
MapStruct **不做 Long ↔ Boolean 的隐式转换**，且这种问题是**编译期**就失败，
不是 `unmappedTargetPolicy = IGNORE` 能盖过去的。

**修法**：`RemoteProctorSessionVo.forceSubmit` 改成 `Long`（与实体一致）。
该 VO 目前只有 Dubbo 的 `queryByRecordId` 在用，没有前端消费方，改类型无副作用。

**顺带对齐前端**：`api/exam/proctor/types.ts` 的 `ProctorSessionVO.forceSubmit` 从 `number`
改成 `string` —— 后端 Long 经 `BigNumberSerializer` 序列化后是字符串（"0" / "1"）。

## 摄像头小窗全黑 + 抓拍纯黑 + 退出全屏只在切屏时记录

### bug A：摄像头画面全黑（`useProctor.openCamera`）

**根因**：答题页的监考卡片是 `<el-card v-if="proctorId">`，而 `start()` 里是
「先赋值 `sessionId.value` → 立刻 `await openCamera()`」。Vue 的 DOM 更新是异步的，
**这一步 `<video>` 元素根本还没渲染出来**，`videoRef.value` 是 `null`，
`srcObject` 压根没挂上 → 小窗黑、canvas 抓出来也是黑的。

**修法**：
- `openCamera()` 里先 `cameraOpen.value = true` 再 `await nextTick()`，元素显示出来才挂流
  （`display:none` 的 `<video>` 在部分浏览器里不解码画面，抓出来是黑的）。
- 加 `waitVideo()` 轮询兜底（最多 3 秒），拿不到就提示「摄像头画面未就绪」。
- 挂完流等 `loadedmetadata`（3 秒超时兜底）再 `play()`，别在第一帧解码完之前抓拍。
- `capture()` 加守卫：`video.readyState < 2 || videoWidth === 0` 直接跳过这一轮
  （画面没出来硬抓必黑，不如等下一轮）。
- 画布按 `videoWidth/videoHeight` 真实比例算高度，避免拉伸黑边。
- 入场抓拍改成重试 5 轮，拿到一张就停。
- 样式：`.proctor-video` 背景从 `#1f1f1f` 改成 `#f5f7fa`（黑底会让人分不清
  「还没拿到画面」和「摄像头是黑的」），并加了「正在获取摄像头画面…」占位。

**通用规则**：在 `v-if` 容器里的元素，**赋值响应式开关后不能立刻取它的 ref**，
必须先 `await nextTick()`（或轮询等挂载）再去挂 `srcObject` / 调 `focus()` 之类。

### bug B：退出全屏只在切屏时被记录

**根因**：只监听 `fullscreenchange`。而 F11 是**浏览器级全屏**（不走 Fullscreen API，
`document.fullscreenElement` 一直是 null，也不触发事件），Esc 退出偶尔也丢事件；
Chrome 在 alt-tab 时会自动退出全屏并触发事件 —— 所以看起来「只有切屏才记」。

**修法**：
- 抽出 `inFullscreenNow()`（兼容 `webkitFullscreenElement`）、
  `markExitFullscreen(reason)`（**只有 `wasFullscreen` 为 true 才计数**，
  避免没进过全屏的人被反复计数）。
- 新增 `checkFullscreen()`，挂进原来 3 秒一次的定时器（和 `checkDevtool` 一起跑）：
  状态类检测不能只靠事件，要定时看真实状态补记。
- `bind()` 里 `wasFullscreen = inFullscreenNow()`，避免把「进来就是全屏」误判成一次退出。
- 补 `enter_fullscreen` 事件（后端 `ProctorEventType` 新增 `ENTER_FULLSCREEN`，
  level=info、不计数），流水里能看出「进去了多久又退出来」。
- `enterFullscreen()` 兼容 `webkitRequestFullscreen`，且**不再乐观置位** `wasFullscreen`。

## 刷新页面后切屏 / 粘贴 / 退出全屏 / 抓拍计数看起来被清零

**根因**：`useProctor` 里这四个计数是**本地 ref，从 0 起算**，只有 `report()` 返回时才会被
服务端值覆盖。刷新后会话是复用的（后端按 examId + recordId resume），服务端计数还在，
但本地又是 0，且在下一次上报之前不会修正 —— 看着就像被清零了。

**修法（核心：服务端计数才是真值，本地那份只是显示）**：
- 抽出 `syncCounts(data)`，统一用服务端值覆盖本地计数（顺带处理 exceed → 强制交卷）。
- `start()` 拿到会话后立刻 `syncCounts(res.data)` —— 续答 / 刷新都能把已有次数带回来。
- `flush()` 复用 `syncCounts`，不再各写一遍。
- **心跳从 `void` 改成返回 `ProctorReportVo`**：每 30 秒把服务端计数拉回来校准一次，
  顺带纠正「多标签页同时上报」造成的本地漂移。
- `ProctorReportVo` 补 `cameraCount`（原来只有 switch/paste/exitFullscreen，抓拍数对不上）。

**通用规则**：计数 / 状态类数据，前端的本地值必须能被服务端值**周期性纠正**，
不能只在发生新事件时才同步 —— 否则刷新、多端并发、上报失败这几种情况都会显示失真。

## 摄像头一直提示「画面未就绪」（真正的根因，前面那次没修干净）

现象：mac 摄像头灯亮、浏览器权限已开，但答题页小窗和抓拍始终黑/提示未就绪。

**真正的根因不在 hook 里，在调用时机**：
`views/exam/answer/index.vue` 的 `loadPaper()` 里，`await startProctorWatch(...)` 写在
`loading.value = false`（在 `finally`）**之前**。而整个答题区是 `<div v-if="loading">` 骨架屏
分支 —— 开摄像头那一刻右侧监考卡片和里面的 `<video>` **根本不存在**，`waitVideo()` 3 秒超时
后判死；随后 loading 变 false 卡片才渲染出来，于是「未就绪」这条错误就永久停在那儿了。

**修法**：
1. `loadPaper()` 里先 `loading.value = false` → `await nextTick()` → 再 `startProctorWatch()`。
2. hook 侧不再依赖单一时序：
   - `<video id="proctor-video">`，`findVideo()` = `videoRef.value ?? getElementById(id)` 双路兜底。
   - 拿不到元素**不判死**：提示改为「正在等待摄像头画面…」，后台 `retryAttach()` 每 2 秒重试 15 轮，
     成功自动清掉错误（时序问题的自愈）。
   - 挂流与等待画面拆开：`attachStream()`（挂 srcObject + `waitFrame()` 等 readyState≥2 且
     videoWidth>0）+ `startCaptureTimer()`。
   - 新增 `keepCameraAlive()` 挂进 3 秒循环：断流自动重挂、`video.paused` 自动 play、
     轨道 ended 时提示「摄像头连接已断开」；新增 `cameraReady` 状态（拿到流 ≠ 有画面）。
   - `capture()` 增加**黑帧检测**（隔点采样算平均亮度 < 6 判黑帧跳过），彻底杜绝上传黑图。
   - `getUserMedia` 失败按 `DOMException.name` 细分文案（NotAllowedError / NotFoundError /
     NotReadableError / OverconstrainedError），并判断 `navigator.mediaDevices` 是否存在
     （非安全上下文直接说明要 HTTPS 或 localhost）。

**通用规则**：**任何依赖 DOM 的副作用（挂流、focus、测量尺寸）都必须在页面真正渲染完之后
才启动**。先看清外层是不是 `v-if` 的 loading / 空态分支，否则副作用启动时元素压根不存在。
另外，这类「等元素出现」的逻辑不要一次超时就永久报错，要留后台重试自愈。

## 切屏只统计了切换标签页，没统计「切到其它软件窗口」

用户反馈：切到别的软件（微信/钉钉/另一个浏览器窗口）不算切屏。

**根因**：`onBlur` 里写的是「`document.hidden` 才 `markSwitch()`，否则只 `push('blur')`」。
但切到**其它应用窗口**时页面并没有 hidden（`document.hidden === false`），
只是浏览器窗口失去焦点 —— 这条路只落了一条 info 级 blur 流水，不计 `switch_count`。

**修法（`useProctor.ts`）**：
- `markSwitch(reason)` 加原因参数，三类来源统一走切屏计数：
  - `onVisibilityChange`（hidden）→ 「切换了浏览器标签页或最小化窗口」
  - `onBlur`（`document.hidden || !document.hasFocus()`）→ 「浏览器窗口失去焦点（切换到了其它窗口或应用）」
  - `checkFocus()` 定时兜底 → 「考试窗口失去焦点（可能切换到了其它应用）」
- 新增 `windowFocused` + `checkFocus()` 挂进 3 秒循环：**blur 事件不是每次都来**
  （mac 调度中心/切换桌面、全屏下 alt-tab、部分浏览器最小化都可能丢事件），
  只在「有焦点 → 没焦点」的**变化沿**上记一次，避免持续离屏被反复计数。
- `bind()` 里初始化 `windowFocused = document.hasFocus() && !document.hidden`，
  避免「在别的窗口打开试卷、页面自己加载完」被误记一次。
- 新增 `onFocus()`：焦点回来时若 `cameraReady` 就抓拍一张 `resume`；
  `markSwitch` 里切走前也抓拍一张 `switch_screen`（监考端能确认屏幕前是谁）。
- 仅当「事件来了但 `document.hasFocus()` 仍为 true」这种极少数情况才退回记 `blur` 流水。

## 上面那版改完：点一次其它窗口，切屏被记两次（回归）

**根因**：每个事件各自维护 `windowFocused`，状态不是现读的，而是「事件说什么就信什么」：

- `onBlur` 无脑 `windowFocused = false`，`onFocus` 无脑 `windowFocused = true`；
- 点一次别的窗口可能只来 blur，也可能 blur 后又补一个 focus/再 blur；
- 于是「有焦点 → 没焦点」的变化沿被判出两次，第二次往往在 3 秒轮询里（>1.5s 节流窗口）；
- 后端只按 `类型 + 事件秒` 去重（且只在**同一批**内去重），隔了几秒的两条各算一次 → 计数 +2。

**修法（`useProctor.ts`）**：
- 新增 `syncFocus(reason, onBack)`：**所有来源（visibilitychange / blur / focus / 3 秒轮询）
  全部收敛到这一个状态机**，状态一律**现读** `document.hasFocus() && !document.hidden`，
  事件只决定「什么时候读、以什么理由记」，不再由事件直接写状态。
- 新增 `awayCounted` 闩锁：`markSwitch` 记过一次后，**必须确认焦点真的回来才解锁**；
  没回来之前的任何信号（blur 补发、轮询、visibilitychange）都不再计数。
  1.5 秒节流降为第二层兜底（防「回来又立刻切走」的抖动）。
- blur 里 `document.hasFocus()` 在 Chrome 下常常还是 true，所以 `onBlur` 改为
  `scheduleFocusCheck()`：0 / 300 / 1200ms 三次**复读**，焦点真正切走后那次才可信。
  当下仍是 focused 时才落一条 info 级 `blur` 流水（不计数）。
- `focusTimers` 用 Set 收集，`unbind()` 里统一 clear。

**通用规则**：一个状态有多个信号源时，状态必须**现读真实值**，事件只当触发器；
「变化沿计数」还要配一个**「本段已记过」的闩锁**，只靠时间节流挡不住
「同源事件补发 + 定时兜底」这种相隔几秒的组合。

## 修：项目起不来，AutoMapperProcessor NPE（cert 模块）

**现象**：编译直接崩在 `AutoMapperProcessor.getSuperClass:841` →
`Optional.of` 抛 `NullPointerException`，栈里全是 mapstruct-plus 的帧，看不出任何业务类名。

**根因**：`CertificateBo` / `CertificateRecordBo` 继承了**不存在**的
`org.dromara.common.core.domain.BaseEntity`（正确的在
`org.dromara.common.mybatis.core.domain.BaseEntity`）。父类解析成 ERROR 类型后
`Types.asElement()` 返回 null，mapstruct-plus 没判空就 `Optional.of()` 炸了 ——

## 答案展示：页面直接贴出了答案 JSON（commit 2d6a9944f）

现象：阅卷打分的「参考答案」显示 `{"answer": "\naaaa\n"}`，练习 / 错题重刷 / 成绩详情同理。

**根因**：`question.answer`（参考答案）和 `exam_answer.answer_content`（考生作答）是
**两套键名不同的 JSON**，而各展示点只认其中一套：

```
参考答案（出题页 question/edit.vue + QuestionImportServiceImpl 写入）
  SINGLE/MULTIPLE/JUDGE : { "rightKeys": ["A","C"] }      判断题 A=正确 B=错误
  BLANK                 : { "blanks": [{ "answers": ["北京","北平"] }] }
  SHORT_ANSWER/ESSAY/UPLOAD_FILE : { "answer": "<p>富文本要点</p>" }
  CODE                  : { "language":"java", "answer":"...", "remark":"..." }
  MATCH（匹配题）        : { "pairs": [{ "left":"CPU","right":"中央处理器" }] }

考生作答（答题页 / 错题重刷写入）
  SINGLE/JUDGE : { "choices": ["A"] }       MULTIPLE: { "choices": ["A","C"] }
  BLANK        : { "blanks": [{ "text": "北京" }] }
  主观题       : { "text": "<p>考生作答</p>" }
```

后端 `MarkServiceImpl.toAnswerText` 只解析 `{"text":..}`，参考答案是 `{"answer":..}`
→ 解析不到就 `return content`，整串 JSON 原样下发；前端 `views/exam/answer/index.vue`
的 `readableAnswer` 同样只认 `choices/blanks[].text/text`。

**修法**：
- 新增 **`src/utils/answer.ts`**：`formatAnswer(raw, questionType, {standard, options, empty})`
  按 `getQuestionTypeMeta().answerMode` 分派翻译，`answerKeys(raw, questionType)` 取客观题标识。
  **两种家族的键都认**（`rightKeys ?? choices`、`answer ?? text`），`standard` 传反也不露 JSON；
  不是 JSON 时（后端已转成人话 / 历史纯文本）原样渲染 —— 所以后端文本里万一还是 JSON 也会被二次翻译。
- 4 个展示点统一改用：`views/system/mark/marking.vue`、`views/exam/records/detail.vue`、
  `views/exam/wrong/practice.vue`、`views/exam/answer/index.vue`。
  后端 `*Text` 字段降级为**兜底**（`raw || text`）—— 阅卷页有 `standardAnswer`/`answerContent`
  原始字段，成绩详情有 `myAnswer`/`standardAnswer`，错题重刷只有文本。
- `records/detail.vue` 的 `splitKeys('A、C')` 换成 `answerKeys()` 直接读原始 JSON。
- **`questionMeta.ts` 从 `views/system/question/` 移到 `src/utils/`**（答案工具要复用题型映射）：
  连带改 `edit.vue`、`hooks/useExamDicts.ts`、`views/system/question/useQuestionDict.ts` 三处 import。
- 后端 `MarkServiceImpl.toAnswerText` 的 `TextAnswer` 补 `answer` 字段（AI 预评 prompt 用得到）。

**通用规则**：
- 展示层拿到的「人话文本」字段只能当兜底，**能拿到原始 JSON 就自己翻译**，
  否则后端一漏解析就是满屏 JSON。
- v-html 插入的内容拿不到 scoped 的 `data-v-` 属性，样式必须写 `:deep(.xxx)`。
- 考生填的纯文本（填空、代码、匹配项）渲染前必须 `escapeHtml`，只有富文本字段能原样输出。

### 架构结论（速记）
五层：L1 模型供应商 → L2 模型网关 AiModelRouter → L3 能力层(工具/Skill/记忆/RAG)
→ L4 编排层(Planner/Executor/Critic/Guardrail) → L5 接入层。
**Guardrail 是一等公民**：写操作工具标 `riskLevel=WRITE`，碰分数/发布的动作一律 HITL。

八种模式定位（按「自动化程度 × 错误代价」）：
- Tool-Augmented = 全场景底座，不单独算模式
- **Reflection 性价比最高**（只多 1 次调用，拦掉大部分低级错误），命题+阅卷必配
- RAG 主攻命题与答疑；ReAct 主攻组卷/诊断；Plan-and-Execute 主攻长流程（**与 ReAct 混合最优**）
- Multi-Agent 只在「错不起」时用（命题流水线、阅卷仲裁），token 是单 Agent 的 2-5 倍
- Memory-Augmented 主攻学情；Autonomous Loop **只放后台巡检**，
  ❌ 自动发布 / 自动定分 / 自动判定作弊 一律禁止

### 多模型主备切换
`WHERE tenant_id=? AND del_flag='0' AND status='0' ORDER BY priority ASC, id ASC` 取主，
失败按 `retry_count` 重试后切下一个；配 **HEALTHY→DEGRADED→FUSE_OPEN→HALF_OPEN** 熔断状态机
（没熔断时，挂掉的模型会被每个请求试一遍，200 人批量阅卷会白等 200 次超时）。
`weight` 本期不参与决策。**全部失败必须抛异常，绝不静默降级为假成功**
（延续 `DefaultMarkAiServiceImpl` 明确返回"未接入"的哲学）。
`ai_model_config` 在 ry-cloud → 需在 `ruoyi-api-system` 新增 `RemoteModelConfigService`，
**禁止 ai 服务直连 system 库**；api_key 不落日志。

### FDE 视角要点
P0 = 模型网关 + AI 主观题预评（两周上线）；先跑**影子模式**（AI 打分不显示，两周后拿一致率
数据说服老师）；单位经济：一场 200 人 × 5 主观题 ≈ ¥1-3，省的是十小时级人力，ROI 压倒性。
最大风险不是 AI 判错，而是**老师无脑全盘采纳** → UI 要做"反惰性设计"（默认只采纳一致项、
批量采纳二次确认、一键回退）。

## 修：进入大屏后「退出大屏」点不动

根因很隐蔽：切换入口挂在 `el-dropdown` 的下拉菜单里。**全屏时浏览器只渲染被全屏的那个
元素**，而 el-dropdown（以及 el-message、el-dialog 等）的弹层默认 `teleport` 到 body ——
全屏后这些弹层**根本不显示**，于是点按钮「毫无反应」，人也出不去。

结论（可复用）：**全屏容器内的交互，绝对不能依赖 teleport 到 body 的弹层**
（dropdown / message / dialog / tooltip 全算）。要么做成内联按钮，要么把 `:teleport="false"`
塞进全屏容器内（注意会被 overflow 裁切）。

改法：大屏切换改成点一下就切的主按钮；右上角加固定定位的圆形退出按钮（大屏内容长，
滚下去就看不到顶部那颗）；`screenfull.request/exit` 包 try/catch —— 之前 await 抛错会

## 考试统计详情页 404（commit 44ecd2edd）

现象：大盘点「详情」跳 `/system/stat/exam?examId=...` 报 404。

**根因**：统计的 5 个页面只靠后台菜单 2120 提供入口，而它生成的是 **`/stat`**（顶层 C 类型菜单
path=`stat`，后端 `SysMenu.getRouterPath()` 对 `isMenuFrame()` 返回 `/`，再由 buildMenus 把
'stat' 塞进 children → `/stat`）。`exam / user / question / knowledge` 四个下钻页**既无菜单也无
静态路由**，而页面里跳转和面包屑全写死 `/system/stat/*` → 必然 404。

**修法**：按 `/system/exam/situation` 的既有惯例，在 `router/index.ts` 注册 hidden 静态路由
`/system/stat/{dashboard,exam,user,question,knowledge}`。

**关键细节**：`activeMenu` 必须写 **`/stat`**（菜单实际生成的地址），写 `/system/stat/dashboard`
高亮不到侧边栏「考试统计」。注意项目里 `/system/exam/edit` 等页的 `activeMenu='/system/exam'`
其实是错的（菜单 path=exam 生成 `/exam`），高亮一直没生效 —— 既有 bug，未动。

**判定「菜单生成什么地址」的方法**（下次别猜）：
`SysMenu.getRouterPath()`：parent_id=0 且 type=M 且非外链 → `"/"+path`；
parent_id=0 且 type=C 且 is_frame=1（isMenuFrame）→ `"/"`，真正的地址落在 children 的 path 上。

顺带修：`views/system/stat/exam/index.vue` 的 `goMark` 原本跳 `/system/mark`（首页不认 examId），
改跳 `/system/mark/record`；`summary` 初始值补 `{} as StatExamRowVO` 断言过类型检查。
