## 错题本模块落地（exam-practice + exam-front）

**归属决策**：错题本放 `ruoyi-exam-practice`（Nacos `ruoyi-exam-practice.yml` 注释已写明「练习记录与错题本归主库」，
pom 已依赖题库/试卷 API，网关 `/practice/**` 已就绪）。考试名来源需要 `RemoteExamService`，给 practice pom 补了
`ruoyi-api-exam-manage`；答题服务 pom 补了 `ruoyi-api-exam-practice`。

**三个关键坑（下次改这类表务必注意）**：
1. `wrong_question` / `wrong_review_record` 缺 `tenant_id`，而 `tenant.enable=true`，
   租户拦截器会给所有表拼 tenant_id → 必须补列（已选补列方案，非 excludes 方案）。
   增量脚本：`script/sql/update/update_exam_wrong_question_tenant.sql`，同时同步了 `ry-exam.sql` 建表语句。
2. **实体不能继承 BaseEntity / TenantEntity**：`InjectionMetaObjectHandler` 会给 BaseEntity 子类注入
   create_by / create_dept / update_by，这两张表没有这些列，继承必然 `Unknown column`。
   所以两个实体写成独立 POJO，字段与 DDL 严格对齐，插入时显式 `setTenantId(TenantHelper.getTenantId())`。
3. 主观题重做无法自动判分：只写 `wrong_review_record` 并提示，不参与掌握度判定，`correct` 返回 null。

**业务规则**：答错/半对才进错题本（挂 `ExamRecordServiceImpl.doSubmit()` 判分后 Dubbo 同步，访客无 userId 跳过）；
答对 1 次提示可移除，连续答对 2 次自动 `MASTERED`（又答错则 rightCount 归零、已掌握退回未掌握）；
用户移除 = `IGNORED`（可找回），彻底删除 = 软删 `is_deleted`。

**判分逻辑重复**：`ExamRecordServiceImpl.judge()` 是私有的，用户要求不新建全局工具类、不动 common 层，
所以在 `WrongQuestionServiceImpl` 内部又写了一份私有 judge（含 OptionAnswer/BlankAnswer/TextAnswer 内部类）。
后续若要 DRY，可考虑在 `ruoyi-api-exam-answer` 暴露判分 Dubbo 接口。

**前端**：Vue3 + TS + Element Plus（用户给的技术栈写的 Vue2+ElementUI 是错的，实际是 Vue3）。
新增 `src/api/exam/wrong/{index.ts,types.ts}`、`views/exam/wrong/index.vue`（总览+来源分组+列表）、
`practice.vue`（逐题重刷、即时判对错、看解析、笔记、重做记录），路由是静态路由加在 `src/router/index.ts`。
`vite build` 通过，ESLint 已 --fix。后端按用户要求**未执行 mvn**。

## 错题本第二轮：按考试记录改造 + 修 BUG

**BUG1 原因（高频坑）**：Vue 模板里写 `@click="goPractice()"` 与 `@click="goPractice"` 完全不同——
后者会把 PointerEvent 当第一个实参传进去，当初 `goPractice(id?)` 收到 PointerEvent，
`String(id)` = `[object PointerEvent]`，最终请求 `/practice/wrong/[object%20PointerEvent]` 404。
**约定**：`<script setup>` 里凡是带可选参数的处理函数，模板中一律写成 `xxx()` 显式调用，或改接收行对象的写法。

**BUG2 选项样式**：Element Plus 的 `el-radio` / `el-checkbox` 默认 `height: 32px` 且 `white-space: nowrap`，
富文本选项会被压扁溢出。修法：`.option-item` 加 `height:auto; min-height:32px; white-space:normal`，
并用 `:deep(.el-radio__label)` 放开换行 + `flex:1`，`:deep(.el-radio__input)` 加 `margin-top` 与内容首行对齐。
同时把选项做成卡片（边框+hover+选中态），判分后按 `standardAnswer` 的 rightKeys 给正确答案标绿、用户错选标红。

**改造3 按考试记录展示**：列表页主视图改成「按考试记录」表格（来源/错题数/未掌握/已掌握/最近答错/查看+重刷），
下方错题明细由选中的记录驱动筛选。后端 `WrongSourceVo` 补了 `notMasterCount` 字段。
practice 页加「本轮范围」下拉（全部错题 / 某场考试），每题顶部有来源条，答题进度条 + 作答回填（切题不丢已答内容）。

**注意**：前端用的原子类是 **UnoCSS**（`import 'virtual:uno.css'`），不是 tailwind，项目里没有 tailwind 配置文件。
**构建注意**：`vite build` 会清空 `dist/assets`，沙箱的安全删除策略会拦截批量删除导致 exit=1；
改用 `--outDir /tmp/xxx` 绕过即可（代码本身没问题）。

## 考试类型（exam_type）改造：正式考试 / 练习考试

**关键设计判断**：`exam_record` 不加 exam_type 冗余列。理由：`listMyRecords` 已有
`examMap.computeIfAbsent(examId, remoteExamService::queryExam)` 缓存批量取 exam，`ExamCenterVo`
更是直接由 `RemoteExamVo` 构造 —— 两个列表场景本就拿得到考试对象，加列是纯冗余还要维护双写一致。
按类型筛选用「半连接」：`RemoteExamService.listExamIdsByType(type)` 先取考试ID，再 `in` 下推 SQL，
分页条数才不会失真。

**展示模式复用 show_answer_mode**：刷题「实时判题」没有新增列，而是给 `show_answer_mode` 增加
取值 `immediate`（做完一题立刻看答案与解析）。正式考试的选项里不给这个值时，避免答案提前泄露。

**起止时间可空**：练习考试长期有效，把 `exam.start_time / end_time` 改成了 NULL 可空。
`isBefore/isAfter/isLate` 本身对 null 返回 false，天然就是「不卡时间窗」，无需改判断逻辑；
`remainingSeconds` 对 duration<=0 返回 -1（不限时），练习不会一进页面就被自动交卷。
必填校验移到 `ExamServiceImpl.checkExamRules(update, exist)`，按 examType 判断，
update 时未带的字段从 exist 兜底，避免误判。

**错题本分类**：`wrong_question` 不动结构，WrongQuestionVo/WrongSourceVo 加 `examType` 展示字段，
`cachedExam()` 与来源名称共用一次 Dubbo 调用，零额外开销。

**规则冲突处理**：用户要求「数据库区分练习/考试」与「不改已有业务表结构」冲突，
已向用户确认后按「加列=扩展」处理，只给 exam 加了一列。
